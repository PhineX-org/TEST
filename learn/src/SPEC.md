# X Code Learn — دليل التأليف (Authoring Spec)

أنت بتكتب منهج برمجة بالعربي المصري على طريقة **freeCodeCamp**: شرح عميق لكل فكرة + تمارين صغيرة بيكتب فيها المتعلّم الكود بنفسه والمنصة بتختبره لحظياً + مشاريع بتتبني **من الملف الفاضي لآخر خطوة**.
المتعلّم = مبتدئ تماماً بيتكلم مصري ومشتغلش برمجة قبل كده. هدفنا يطلع مبرمج محترف في الآخر، فالعمق مهم: اشرح *ليه* مش *إيه* بس.

**اقرا الأمثلة الذهبية الأول وقلّدها في العمق والنبرة والبنية:**
- درس: `learn/src/html/u1-first-page/03-headings-paragraphs.md`
- مشروع: `learn/src/html/u1-first-page/08-profile-page/` (project.md + index.html)

## 0. القواعد الذهبية

1. **اللغة = عامية مصرية** (مطلب صارم من صاحب الموقع). اكتب زي مدرس مصري بيشرح لصاحبه: «ده/دي/دول»، «اللي»، «كده»، «عشان»، «هتلاقي»، «مش»، «إزاي»، «ليه»، «إمتى»، «لسه»، «أوي»، «شوية»، «تخيّل كده»، «بص»، «خلّي بالك». ممنوع الفصحى الجامدة: «يُعتبر»، «حيث إن»، «وذلك»، «لذا»، «قم بـ»، «يمكنك»، «سوف»، «لا يوجد»، «هذا/هذه». استخدم «تقدر»، «هـ…»، «مفيش»، «ده/دي». كلمات البرمجة تفضل إنجليزي في `backticks` أو عادي (browser, tag, function, array…)، وتتشرح أول مرة بكلام بسيط. **المصطلح المهني الإنجليزي أحسن من الترجمة العربي الركيكة**: بنقول `padding` و`margin` و`flexbox` و`callback` مش «حشو» ولا «هامش». مخاطبة القارئ بـ«انت». جمل قصيرة. من غير إيموجي جوه الفقرات (الإيموجي بس في عناوين الأقسام `##` وفي الـ callouts اللي بتتحط تلقائي).
2. **العمق**: لكل مفهوم: (١) إيه هو في جملة بسيطة (٢) تشبيه من الحياة (٣) المتصفح/المفسّر بيعمل إيه فعلاً (٤) الفخ الشائع (٥) مثال صغير ثم مثال واقعي. اشرح الكود سطر بسطر لما يبدأ فكرة جديدة. متقفش عند «ده بيعمل كذا»: قول **ليه موجود** و**إيه اللي بيبوظ لو غلطت**.
3. **الدقة قبل أي حاجة.** متخترعش خصائص أو سلوك. لو مش متأكد 100% اسأل WebSearch (mode `standard`) على MDN. (WebFetch مش متاح.) لو الميزة تجريبية قول كده.
4. **تعلّم بالعمل**: كل درس فيه تمرين `:::try` واحد على الأقل (الدروس الكبيرة 2–3)، وكل خطوة مشروع صغيرة (سطرين لـ ١٠ سطور تغيير) ومعاها اختبارات.
5. **من الصفر**: مفيش مفهوم يتستخدم قبل ما يتشرح (راجع ترتيب الدروس في `PLAN.md`: اللي قبلك اتشرح، اللي بعدك لأ). لو محتاج حاجة لسه متشرحتش، استخدمها من غير شرح *بس لو كانت موجودة جاهزة في الـ starter* وقول «هنفهمها بعدين».
6. لا تكتب placeholders (TODO / lorem ipsum). لا تنسخ MDN حرفياً. الأمثلة واقعية (أسماء وأسعار وجمل بالعربي).
7. **قيود التشغيل**: المعاينة بتشتغل في iframe معزول: **مفيش شبكة مضمونة** (الاختبارات متعتمدش على API خارجي)، مفيش صور خارجية (استخدم emoji أو SVG inline أو `background` ألوان/تدرّجات؛ صورة `<img src="x.jpg">` مش هتظهر)، `alert/prompt/confirm` متاحة بس بتعطّل الاختبارات: **متستخدمهاش في الخطوات**.

## 1. هيكل الملفات

```
learn/src/<track>/track.json                 (متعدّل بمعرفتي — متلمسوش)
learn/src/<track>/<unit>/NN-<id>.md          درس أو اختبار وحدة

```
- الـ `id` = اسم الملف/الفولدر **من غير الرقم** (`03-headings-paragraphs.md` ⇒ `id: headings-paragraphs`). الـ id فريد جوه المسار كله.
- الترتيب = ترتيب اسم الملف (`01-`, `02-`…).
- اشتغل بس على الملفات اللي اتكلّفت بيها في `PLAN.md`. متعدّلش `tools/` ولا `assets/` ولا `track.json`.

## 2. درس (`*.md`)

```
---
id: flexbox-basics
type: lesson
title: أساسيات Flexbox            ← 2–5 كلمات
summary: جملة واحدة 20–200 حرف تظهر في البحث وفي الكروت.
time: 15                          ← دقايق (12–25 للدرس الطبيعي)
level: مبتدئ                      ← مبتدئ | متوسط | متقدم
tags: flex, layout, css           ← اختياري، بالإنجليزي
runtime: tailwind                 ← اختياري (tailwind بس لمسار Tailwind)
---
## 🧭 فكرة الدرس              ← كل قسم: ## + إيموجي + عنوان
...
## quiz                          ← أسئلة آخر الدرس (٣–٥)
```

الدرس المتوسط **٥–٨ أقسام**: فكرة/تشبيه → شرح مع أمثلة live متدرّجة → `:::try` → أخطاء شائعة (compare) → ملخص → `## quiz`. حجم النثر (من غير الكود) ≥ ٣٠٠٠ حرف، والدرس الكامل ٧–١٤ KB.

### كتل المحتوى المسموحة جوه الأقسام

| الصيغة | بتطلّع |
|---|---|
| فقرات عادية (سطر فاضي بين فقرة وفقرة) | فقرة. جوه الفقرة: `` `code` `` و`**غامق**` و`*مائل*` |
| `### عنوان` | عنوان فرعي |
| `- بند` / `1. بند` | قايمة نقطية / مرقّمة |
| `+ بند` / `~ بند` | قايمة ✓ (صح/افعل) / قايمة ✗ (غلط/متعملش) |
| `- [ ] بند` | قايمة checkboxes (للمراجعة) |
| `> [!tip] نص` (أنواع: `tip` `warn` `note` `analogy` `key`) | callout. فقرات تانية بسطر `>` فاضي |
| ```` ```html ```` / `css` / `js` / `python` / `php` / `jsx` / `bash` / `json` / `text` | كود ثابت (highlight بس) |
| ```` ```html live ```` (+ `h=300` للارتفاع) | **مثال شغّال** (المتعلّم يعدّل عليه ويشوف النتيجة) — `html` بس (ممكن فيه `<style>` و`<script>`) |
| ```` ```html bad ```` متبوعة بـ ```` ```html good ```` | مقارنة غلط/صح جنب بعض |
| ```` ```out ```` | ناتج التنفيذ (Output) |
| جدول `\| a \| b \|` + `\|---\|---\|` | جدول |
| `:::steps` سطور `عنوان :: شرح` `:::` | خطوات مرقّمة بدواير |
| `:::terms` سطور `مصطلح :: تعريف` `:::` | قاموس مصطلحات |

ممنوع: HTML خام خارج backticks، عناوين `#`/`##` جوه القسم، قوايم متداخلة. سطور الكود ≤ 80 حرف (موبايل). مسافتين indent.
كل وسم HTML بتذكره في الشرح يتكتب في backticks: `` `<div>` ``.

### التمرين `:::try` (جوه الدرس)

```
:::try html title="اعمل صفحة تعريف" h=220
نص المهمة (فقرات/قوايم عادية). قول المطلوب بالظبط.
---starter
<!-- الكود اللي بيبدأ بيه المتعلّم -->
---tests
وصف الاختبار بالعربي (بيظهر للمتعلّم) :: تعبير JavaScript يرجّع true
اختبار تاني @420 :: ...       ← @420 = شغّله بعرض 420px (media queries)
---solution
<الحل الصحيح>
---hint
تلميح اختياري (markdown inline).
:::
```
- اللغة بعد `try`: `html` (المحرر = `index.html`، وممكن `---css` و`---js` يضيفوا ملفات `style.css` و`script.js` مربوطة تلقائياً) أو `css` (المحرر = `style.css` والصفحة ثابتة في `---html`) أو `js` (المحرر = `script.js` والصفحة في `---html`، الافتراضي `<div id="out"></div>`).
- `---solution` بيتحط مكان الملف اللي بيتعدّل (index.html / style.css / script.js).
- **الاختبارات لازم**: (أ) تفشل على الـ starter، (ب) تعدّي على الـ solution، (ج) تقبل كل حل صحيح تاني (متتمسكش بمسافات/علامات اقتباس/ترتيب خصائص)، (د) ٢–٦ اختبارات، وكل وصف بيقول المطلوب (مش «اختبار 1»).

```
- [ ] اختيار غلط
- [x] اختيار صح (واحد بس)
- [ ] اختيار غلط
- [ ] اختيار غلط

شرح الإجابة (ليه الصح صح وليه الباقي غلط).
```
٣–٥ أسئلة للدرس: ما بين «إيه ده؟» و«إيه ناتج الكود؟» و«لاقي الغلط». الاختيارات تتشاف بالشكل نفسه (نفس الطول تقريباً)، والإجابة الصح مش دايماً أطولها. ٣–٥ اختيارات.

### اختبار الوحدة (`type: quiz`)

ملف `NN-<id>.md` (الاسم زي `09-html-quiz-1.md` ⇒ `id: html-quiz-1`، والـ id المحدد في `PLAN.md`): front matter بنفس الحقول (من غير `time`/`runtime`)، وجسمه أسئلة بنفس صيغة `## quiz` تحت قسم واحد `## quiz`. **٨–١٢ سؤال** بتغطي الوحدة كلها، منها أسئلة كود.

**عدد الخطوات**: المشروع الصغير ٦–٩، الطبيعي ٩–١٤، الكبير (landing page / portfolio) ١٤–٢٠. كل خطوة = فكرة واحدة وتغيير صغير مرئي. **المتعلّم بيبدأ من ملف فاضي** (الخطوة ١ = الهيكل). مفيش خطوة «اكتب ٥٠ سطر».

### الـ markers (الكود بيتكتب **مرة واحدة** بشكله النهائي)

كل سطر في ملفات المشروع بيظهر من خطوة معيّنة وللآخر. علّم الأسطر بـ marker (على سطر لوحده):

| الملف | فتح | قفل |
|---|---|---|
| HTML | `<!--@3-->` | `<!--@/-->` |
| CSS | `/*@3*/` | `/*@/*/` |
| JS / PHP | `//@3` | `//@/` |
| Python | `#@3` | `#@/` |

- `@3` = من الخطوة ٣ وللآخر. `@3-6` = من ٣ لـ ٦ بس (بيتبدّل بعدها بنسخة تانية بـ `@7`).
- الأسطر من غير marker موجودة من الخطوة ٠ (الملف الفاضي ممكن يبقى كله marked).
- الـ regions ممكن تتداخل. بيتحوّلوا لحالة الملف **بعد** الخطوة k.
- **أي خطوة لازم تغيّر ملف** (marker بيبدأ أو بينتهي عندها)، وأعلى رقم marker = عدد الخطوات بالظبط.
- الحالة بعد كل خطوة لازم تكون كود شغّال (JS: syntax صح) — المتعلّم بيشوف النتيجة بعد كل خطوة.
- الخطوة ١ في HTML = الهيكل كله `<!DOCTYPE html>…` بيتكتب من الصفر. باقي الأسطر بتتضاف جواه (لو سطر بيتعدّل بنسخة جديدة استخدم `@a-b` ثم `@c`).
- **ملف الـ CSS/JS** لازم يتربط من الـ HTML في خطوة صريحة (`<link rel="stylesheet" href="style.css">` / `<script src="script.js"></script>`) — بتتعلّم الربط كخطوة. الملف اللي مش مربوط **مش بيتطبّق**.

### الـ tests

```
:::tests
وصف بالعربي بيقول المطلوب :: تعبير JS يرجّع true
وصف بـ viewport @420 :: ...
  سطر تكملة لو الاختبار طويل (مسافتين في أول السطر)
:::
```
الاختبار = تعبير JS (أو جسم دالة فيها `return`) بيتنفّذ **جوه صفحة المتعلّم** (`with(H)`)، وأي نص يرجع منه = رسالة فشل. **لازم يرجّع boolean.** بيشتغل في نسخة مخفية جديدة من الصفحة (عرض 900px، أو عرض الـ `@N`)، فمفيش تأثير لشاشة المتعلّم.

**الـ helpers** (متاحة كأسماء مباشرة):

| helper | بيعمل |
|---|---|
| `$('sel')` / `$$('sel')` | `querySelector` / `querySelectorAll` (مصفوفة) |
| `txt('sel')` | نص العنصر (مسافات موحّدة) |
| `css('sel','prop')` | الـ **computed style** (قيم محسوبة بالـ px، مثلاً `16px`، ألوان `rgb(...)`) |
| `colorIs('sel','prop','#ff0000')` | مقارنة لون (أي صيغة: hex/rgb/hsl/oklch) ±4 |
| `rgb('red')` | تحويل أي لون لـ `rgb(r, g, b)` |
| `rect('sel')` | `getBoundingClientRect()` |
| `click('sel')` · `type('sel','قيمة')` · `check('sel')` · `submit('form')` · `key('sel','Enter')` | تحاكي تفاعل المستخدم |
| `await wait(100)` | انتظر (للـ animation / `setTimeout`) |
| `ls('key')` | قراءة `localStorage` (معزول جوه المعاينة) |
| `logs` · `out()` | مصفوفة اللي اتطبع بـ `console.log` / النص كله — **الـ console.log على array بيتسجّل JSON: `[1,2,3]`، object: `{"a":1}`** |
| `ev('expr')` | بيقيّم تعبير في الـ global scope بتاع كود المتعلّم (بيشوف `let`/`const`/الدوال): `ev('total') === 30` |
| `src.main` / `src.html` / `src.css` / `src.js` / `src.files['x.js']` | **نص** الملفات اللي كتبها المتعلّم |
| `errors` | مصفوفة أخطاء runtime (`errors.length === 0`) |
| `doc`, `win` | `document`, `window` |

قواعد الاختبارات الجيدة (مهمة جداً):
- **اختبر السلوك والنتيجة** مش النص حرفياً. `css('.btn','display') === 'flex'` أحسن من `src.css.includes('display: flex')`. استخدم regex بدل `includes` لما لازم، مع `i` وتساهل في المسافات وعلامات الاقتباس.
- لو لازم تختبر النص: `/\bdisplay\s*:\s*flex\b/.test(src.css)`.
- **اختبار على الأقل يفشل لو الخطوة متعملتش** (الـ starter مينفعش يعدّي)، ٢–٦ اختبارات للخطوة، **الوصف يقول المطلوب** («الـ h1 جوه الـ header»).
- الـ HTML الكامل: `<!DOCTYPE html>` متتأكدش منه بـ `document.doctype` (دايماً موجود)، استخدم `/^\s*<!doctype html>/i.test(src.main)`.
- للـ CSS على ألوان Tailwind v4 استخدم hex تقريبي مع `colorIs` (مثلاً `blue-600` = `#155dfc`).
- لو الاختبار بيحتاج المتعلّم يتفاعل (click/type) اعمله جواه بـ helpers واستنى بـ `await wait(50)`.
- متستخدمش أرقام أبعاد دقيقة (±) إلا لو الخطوة بتطلبها بالظبط.

## 5. الجودة (راجع نفسك قبل ما تخلّص)

- هل طفل عنده ١٤ سنة مصري يفهم كل جملة؟ هل فيه كلمة تقنية اتستخدمت قبل ما تتشرح؟
- هل الأمثلة بتتدرّج (كل مثال بيزوّد فكرة)؟ هل المثال الـ `live` بيبيّن حاجة **مرئية**؟
- هل الأخطاء الشائعة (compare) حقيقية؟ هل كل معلومة صح؟
- مشروعك بيطلع **صفحة حلوة فعلاً** (ألوان متناسقة، spacing، أمثلة بمحتوى عربي واقعي)، مش اختبار فني.
- حجم الشغل: اكتب كل ملف **مرة واحدة صح** ثم `check` ثم صلّح بتعديلات صغيرة. متعملش screenshots إلا للضرورة.
